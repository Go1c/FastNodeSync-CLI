# FastNodeSync-CLI v3.5.1 分页控制协议适配设计文档

- **设计日期**：2026-07-15
- **协议版本目标**：FNS Server v3.5.1
- **核心策略**：模块自治设计（方案一，不引入多余抽象继承，保持各模块解耦与独立性）

---

## 1. 需求与背景概述

FNS 服务器在 v3.5.1 引入了分页（Page）控制协议。旧版（v0.2.0 等）协议中，服务器在发送 `*SyncEnd` 消息后会立刻主动下发全部待同步数据。
新版 v3.5.1 协议核心变更如下：
1. **启动下载握手**：服务器下发 `*SyncEnd` 后暂停发送数据，等待客户端主动回应 `*SyncPageAck(pageIndex=-1)` 确认启动下载；
2. **逐页分批传输**：服务器分批下发 `*SyncPage` 控制帧及具体的 `*SyncModify` / `*SyncDelete` 数据帧；
3. **逐页响应握手**：客户端根据 `*SyncPage` 控制帧（及其 `pageIndex` / `isLast` 状态），回传 `*SyncPageAck(pageIndex=N)` 以继续请求下一页或确认最终页，直到数据收齐并完成同步。

---

## 2. 核心设计原则

- **简洁优先**：直接针对涉及的 4 个同步模块（`NoteSync`、`FileSync`、`SettingSync`、`FolderSync`）进行内聚适配，不创建单次使用的抽象层或继承基类；
- **精准修改**：仅新增协议要求的消息处理器、上下文状态记录和 PageAck 响应方法，保持已有的 `_on_sync_modify`、`_on_sync_delete` 数据写入逻辑和 `_check_all_received` 计数判断机制完全不变；
- **匹配现有风格**：针对此前尚未完整实现处理 `_on_sync_end` 的 `FolderSync`，对标 `NoteSync` 的架构风格进行规范化补齐。

---

## 3. 详细设计要点

### 3.1 协议常量定义 (`fns_cli/protocol.py`)

新增以下 8 个 Action 字符串常量，分属 4 个同步子模块：

```python
# ── Client → Server actions (分页应答) ────────────────────────────────
ACTION_NOTE_SYNC_PAGE_ACK = "NoteSyncPageAck"
ACTION_FILE_SYNC_PAGE_ACK = "FileSyncPageAck"
ACTION_SETTING_SYNC_PAGE_ACK = "SettingSyncPageAck"
ACTION_FOLDER_SYNC_PAGE_ACK = "FolderSyncPageAck"

# ── Server → Client actions (分页下发) ────────────────────────────────
ACTION_NOTE_SYNC_PAGE = "NoteSyncPage"
ACTION_FILE_SYNC_PAGE = "FileSyncPage"
ACTION_SETTING_SYNC_PAGE = "SettingSyncPage"
ACTION_FOLDER_SYNC_PAGE = "FolderSyncPage"
```

### 3.2 客户端日志与底座适配 (`fns_cli/client.py`)

在 `client.py` 的 `_handle_text(self, raw: str)` 方法中：
- 梳理未在 `self._handlers` 注册的白名单动作（如 `ACTION_AUTHORIZATION` 和 `ACTION_CLIENT_INFO` 均在开头静默处理或由专用回调拦截）；
- 对于可能收到的纯回馈帧或额外非业务处理帧，防止进入默认 `log.warning("Unhandled action from server: %s", msg.action)` 报错，确保客户端排错日志清爽准确。

---

### 3.3 笔记与设置同步模块适配 (`fns_cli/note_sync.py` & `fns_cli/setting_sync.py`)

两者的协议流与完成条件结构完全对应，采取相同的适配方案：

1. **新增状态属性**：
   在类实例中新增 `self._sync_context: str = ""` 和 `self._sync_vault: str = ""`；并在各自的 `_reset_counters()` 中初始化为 `""`。
2. **注册 Page 监听**：
   在 `register_handlers()` 中注册 `ws.on(ACTION_NOTE_SYNC_PAGE, self._on_sync_page)` （设置同步为 `ACTION_SETTING_SYNC_PAGE`）。
3. **新增发送方法**：
   实现 `async def _send_page_ack(self, context: str, page_index: int, vault: str) -> None:`，封装 `WSMessage` 发送。
4. **改造 `_on_sync_end(self, msg: WSMessage)`**：
   - 从 `msg.data` 顶层字段提取并保存 `context` (`msg.data.get("context", "")`) 和 `vault` (`msg.data.get("vault", "")`)；
   - 提取 `needModifyCount` 和 `needDeleteCount` 后计算 `total_expected = self._expected_modify + self._expected_delete`；
   - 若 `total_expected == 0`：标记 `self._sync_complete = True` 并在 `NoteSync` 中调用 `self._commit_last_time()`；
   - 若 `total_expected > 0`：立即发送初始请求帧启动推流：`await self._send_page_ack(self._sync_context, -1, self._sync_vault)`；调用 `self._check_all_received()` 兜底。
5. **新增 `_on_sync_page(self, msg: WSMessage)`**：
   - 使用 `_extract_inner(msg.data)` 提取内层参数，获取 `pageIndex` 和 `isLast` 状态；
   - 采用“到达即应”的异步并发策略：当 `not is_last and pageIndex >= 0` 时，立即回应 `await self._send_page_ack(self._sync_context, pageIndex, self._sync_vault)` 请求下一页；
   - 每次收到 `_on_sync_page` 时同步触发 `self._check_all_received()`；具体的条目收齐判断仍由已有的 `_check_all_received()` (当 `total_received >= total_expected` 时) 统一决定。

---

### 3.4 文件同步模块适配 (`fns_cli/file_sync.py`)

`FileSync` 与 `NoteSync/SettingSync` 的基础握手模式相同，区别在于其收齐完成检查包含了异步文件块下载队列的校验：

1. **新增属性与初始化**：
   添加 `self._sync_context` 和 `self._sync_vault` 成员变量。
2. **注册监听与发送方法**：
   在 `register_handlers()` 中监听 `ACTION_FILE_SYNC_PAGE`，并增加 `_send_page_ack()` 发送 `ACTION_FILE_SYNC_PAGE_ACK` 消息。
3. **改造 `_on_sync_end(self, msg: WSMessage)`**：
   - 提取保存 `context` 与 `vault`；
   - 当 `self._expected_modify + self._expected_delete > 0` 时，调用 `await self._send_page_ack(self._sync_context, -1, self._sync_vault)` 启动下载；
   - 调用 `self._check_complete()`。
4. **新增 `_on_sync_page(self, msg: WSMessage)`**：
   - 解析 `pageIndex` 与 `isLast`；若非末页 (`not is_last and pageIndex >= 0`) 则应答 `PageAck(pageIndex)`；
   - 触发 `self._check_complete()` 校验。由于 `_check_complete` 判断了 `not self._pending_download_paths and not self._download_sessions`，仅在分块全下完且数量达标时才会置 `is_sync_complete = True`。

---

### 3.5 文件夹同步补全与适配 (`fns_cli/folder_sync.py`)

为保证协议一致性与严谨性，对原有缺少 End 监听与数量校验的 `FolderSync` 进行全面补齐：

1. **补全状态统计属性**：
   在 `FolderSync` 的 `__init__` 中新增：
   - `_sync_context: str = ""`
   - `_sync_vault: str = ""`
   - `_expected_modify: int = 0`
   - `_expected_delete: int = 0`
   - `_received_modify: int = 0`
   - `_received_delete: int = 0`
   - `_got_end: bool = False`
   - `_sync_complete: bool = False`
2. **注册完整监听**：
   在 `register_handlers()` 补充监听：
   - `ws.on(ACTION_FOLDER_SYNC_END, self._on_sync_end)`
   - `ws.on(ACTION_FOLDER_SYNC_PAGE, self._on_sync_page)`
3. **改造事件处理方法**：
   - 新增 `_send_page_ack`、`_on_sync_end` 和 `_on_sync_page` 方法；
   - 在已有的 `_on_sync_modify` 执行完毕后执行 `self._received_modify += 1` 并在末尾调用 `self._check_all_received()`；
   - 在已有的 `_on_sync_delete` 执行完毕后执行 `self._received_delete += 1` 并在末尾调用 `self._check_all_received()`；
   - 新增 `_check_all_received()` 方法判断 `_got_end and (self._received_modify + self._received_delete >= self._expected_modify + self._expected_delete)` 从而置 `_sync_complete = True`。
